================================================================================
AI 返回信息的渲染问题分析
================================================================================

一句话结论:
  流式输出的 AI 正文用的是纯文本 textContent 追加,完全没走 marked 管线,
  所以你看到的"正文不是 markdown"是真的没渲染,不是样式问题。


--------------------------------------------------------------------------------
1. 关键代码位置
--------------------------------------------------------------------------------

文件: static/app.js
函数: sendMessage() 内,SSE 事件循环

  第 2062-2071 行 (content_delta 事件):
      } else if (evName === 'content_delta') {
        if (!answerEl) {
          const built = makeStreamBubble(loading, 'msg-assistant msg-stream-answer');
          answerEl = built.bubble;

        }
        answerTextEl.textContent += evData.text;   <-- 纯文本追加

  第 2087-2091 行 (done 事件):
      } else if (evName === 'done') {

        if (thinkEl)  thinkEl.parentElement?.classList.add('msg-stream-done');
        <-- 没有把 answerTextEl 的累积文本重新用 marked 渲染
      }

  第 2116-2121 行 (流式跑完后):
      const lastAssistant = [...history].reverse().find(m => m.role === 'assistant');
      if (lastAssistant && !Array.isArray(lastAssistant.tool_calls) && lastAssistant.content
          && finalData.stopped === 'answer' && !streamedAnswer) {

文件: static/app.js
函数: makeStreamBubble() 第 2159-2179 行

      const text = document.createElement('div');

      <-- 这个 div 自始至终是纯文本容器,流式期间从不换 innerHTML


--------------------------------------------------------------------------------
2. 三种场景下,渲染管线完全不同
--------------------------------------------------------------------------------

场景 A: 流式 (flow=True,当前 .config.json 默认)
  - 走 SSE,收到 content_delta 就 textContent 追加
  - done 时没补渲染
  - 4 个 AND 条件只要不满足就跳过 appendMessage
  - 结果: 看到的是 ###### 标题、```代码块、- 列表 的纯文本字符
  - 状态: ❌ 完全没渲染 markdown

场景 B: 非流式 (flow=False)
  - 后端走普通 model_request
  - streamedAnswer === false 触发 appendMessage
  - 走 formatMarkdownLite -> marked.parse + DOMPurify.sanitize
  - 结果: ✅ 正常 markdown

场景 C: 刷新页面
  - loadChat() -> renderHistory() -> appendHistoryNode() -> appendMessage()
  - 走 formatMarkdownLite
  - 结果: ✅ 正常 markdown

所以同一个 AI 回复,流式时和刷新后看到的不一样,流式没排版,刷新一下突然排版了。

验证 .config.json:
  {
      "flow": "true",
      "max_round": 20
  }
  flow=true 走流式,也就是说你 99% 看到的是场景 A,纯文本。

--------------------------------------------------------------------------------
4. 为什么 4 个 AND 条件几乎不会全部满足
--------------------------------------------------------------------------------

第 2117-2120 行的条件:
  1. !Array.isArray(lastAssistant.tool_calls)
     有 tool_calls 时为 false
  2. lastAssistant.content
     AI 没返回 content 时为 false
  3. finalData.stopped === 'answer'
     流式停在 pending / max_rounds / error 都为 false
  4. !streamedAnswer
     流式只要收到一条 content_delta 就变 true,这条就跳过

  关键: 4 是关键。流式收到正文 -> streamedAnswer=true -> 跳过 appendMessage。
  但流式本身是 textContent 追加,没渲染 markdown。
  两边都跳过了,正文就没排版了。


--------------------------------------------------------------------------------
5. 修复方案 (按优先级)
--------------------------------------------------------------------------------

方案 P0: done 事件里补一次 marked 渲染 (推荐,改 2 行)

  static/app.js 第 2087-2091 行,改成:

      } else if (evName === 'done') {
        finalData = evData;
        if (answerEl && answerTextEl && answerTextEl.textContent) {
          answerTextEl.innerHTML = formatMarkdownLite(answerTextEl.textContent);
        }
        if (answerEl) answerEl.parentElement?.classList.add('msg-stream-done');
        if (thinkEl)  thinkEl.parentElement?.classList.add('msg-stream-done');
      }

  效果: 流式过程中纯文本打字 (快), done 那一刻重排版 (稳)。
  不影响刷新回放,不影响非流式,只补漏。

  同时把第 2116-2121 行那 4 个条件简化,避免重复追加气泡:

      if (lastAssistant && !streamedAnswer
          && !Array.isArray(lastAssistant.tool_calls)
          && lastAssistant.content && finalData.stopped === 'answer') {
        appendMessage('assistant', lastAssistant.content);
      }


方案 P0: CSS 溢出保护

  static/style.css 第 1014 行附近,加:

      .msg-bubble {
        padding: 10px 12px;
        border-radius: 8px;
        line-height: 1.55;
        font-size: 13px;
        overflow-x: auto;
        overflow-wrap: break-word;
        word-break: break-word;
        max-width: 100%;
      }

      .msg-bubble pre {
        overflow-x: auto;
        max-width: 100%;
        white-space: pre;
        background: var(--bg-base);
        border: 1px solid var(--border);
        border-radius: 4px;

      }

      .msg-bubble pre code { white-space: pre; }

      .msg-thinking .msg-bubble {
        max-height: 240px;
        overflow-y: auto;
      }


方案 P1: 实时流式 markdown (可选,有副作用)

  static/app.js 第 2062 行附近:

      let renderTimer = null;
      function scheduleReRender() {
        if (renderTimer) return;
        renderTimer = setTimeout(() => {
          renderTimer = null;
          if (answerTextEl && answerTextEl.textContent) {
            answerTextEl.innerHTML = formatMarkdownLite(answerTextEl.textContent);
            scrollToBottom();
          }
        }, 250);
      }

      } else if (evName === 'content_delta') {
        if (!answerEl) { ... }
        answerTextEl.textContent += evData.text;
        scheduleReRender();   <-- 新增
        streamedAnswer = true;
        scrollToBottom();
      }

  副作用:
    - 半截 markdown 会闪一下 (比如 收到 <pr 时先渲成 <p>pr, 再渲 <p>pro)
    - 性能开销高 (每次都跑 marked)
    - 不完整代码块边界 (```py 没换行时 marked 不知道是代码块)

  所以一般项目更倾向 P0 方案:流式纯文本打字, done 一次性重排。


--------------------------------------------------------------------------------
6. 总结
--------------------------------------------------------------------------------

问题:    流式 AI 正文用 textContent 追加,不走 marked
影响:    你看到的是带 ``` # - 等字符的纯文本,不是 markdown 渲染
根因:    1. content_delta 用 textContent (app.js:2069)
        2. done 事件没补渲染 (app.js:2087-2091)
        3. 第 2116-2121 行 4 个 AND 条件,流式下被 !streamedAnswer 卡掉
        4. CSS .msg-bubble 没溢出保护
修复:    done 里加一次 formatMarkdownLite,2 行 JS + 几条 CSS
确认:    改完只影响: 流式结束后,正文气泡从纯文本变 markdown 排版
        不影响: 思考块、工具调用、待确认卡、刷新回放、非流式
